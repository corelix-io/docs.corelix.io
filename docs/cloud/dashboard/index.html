Dashboard

The Corelix dashboard at app.corelix.io is your central control plane for managing applications, databases, services, and infrastructure.

Navigation​

The left sidebar provides access to all major sections:

SectionDescription
ProjectsYour applications organized by project
ServersInfrastructure management and monitoring
SettingsTeam, API tokens, storage, and preferences

Projects and Environments​

Projects are the top-level organizational unit. Each project contains one or more environments (e.g., production, staging, development).

Creating a Project​

  1. Click New Project from the dashboard.
  2. Give it a name and optional description.
  3. A default production environment is created automatically.

Managing Environments​

Each environment is an isolated space for your resources:

  • Applications — Web apps, APIs, workers.
  • Databases — PostgreSQL, MySQL, MongoDB, Redis, and 50+ more.
  • Services — One-click services from 100+ templates (Plausible, Minio, Grafana, etc.).

Environments provide logical separation. Resources in different environments are independently configurable and deployable.

Resource Actions​

For any application, database, or service you can:

  • Start / Stop / Restart — Control the running state.
  • Deploy — Trigger a new deployment (applications).
  • View Logs — Stream container logs in real-time.
  • Environment Variables — Manage configuration securely.
  • Domains — Add custom domains with automatic SSL.
  • Persistent Storage — Attach volumes for data that survives restarts.

Server Management​

The Servers page shows all connected servers with their health status.

For each server you can view:

  • Status — Online, offline, or provisioning.
  • Resources — Applications, databases, and services running on the server.
  • Docker version — The installed Docker Engine version.
  • Proxy — Traefik or Caddy reverse proxy status.

See Server Provisioning for adding new servers.

Deployment Monitoring​

Every application deployment is logged with:

  • Build logs — Full output from the build process, streamed in real-time.
  • Status — Queued, in progress, succeeded, or failed.
  • Duration — How long the build and deployment took.
  • Commit — The Git commit that triggered the deployment.

You can view deployment history for any application and roll back to previous successful deployments.

Team Collaboration​

Manage your team from Settings > Team:

  • Invite members — Add team members by email.
  • Roles — Assign roles (Owner, Admin, Member, Viewer).
  • Granular permissions — Control project and environment access per user with three permission levels:
    • view_only — Can view resources but cannot modify or deploy.
    • deploy — Can view and trigger deployments.
    • full_access — Full control including configuration and deletion.
Pro Feature

Granular project and environment permissions are available on Pro, Team, and Enterprise plans.

Settings and Preferences​

The Settings area includes:
