DNS Provider Management Free

Automatic DNS records and tunnel ingress for deployed resources — with optional Pro depth for multi-domain, per-hostname routing, and drift sync.

Overview​

DNS Provider Management connects your Corelix instance to external DNS providers and keeps records in sync with your deployments. The first supported driver is Cloudflare Tunnel with Corelix-managed cloudflared.

When you deploy an application or service with an FQDN on a managed domain, Corelix automatically:

  • Creates or updates DNS records (wildcard CNAME or per-hostname records)
  • Configures tunnel ingress rules
  • Shows sync status on each resource's Domains panel
Wildcard routing

Apps under a wildcard-mode domain (*.example.com) are routed automatically — no per-deploy DNS API calls are needed once the domain is provisioned.

Getting Started​

  1. Enable the feature: set CORELIX_DNS_PROVIDER_MANAGEMENT=true in your environment.
  2. Go to Settings → DNS Providers and add a Cloudflare provider with your API token.
  3. Add a managed domain and bind it to a server.
  4. Deploy resources with FQDNs — DNS reconciles automatically after deployment.

Per-Resource Domains Panel​

Each application and service has a Domains configuration tab showing:

  • Hostname sync state (synced, pending, error)
  • Domain assignment and pinning (Pro)
  • Manual re-sync for owners/admins

Pro Features​

Upgrade to Team or enable Pro DNS children for:

FeatureDescription
Multi-DomainMultiple providers and domains per team
Per-Hostname RoutingIndividual CNAME + ingress rules per host
Environment BindingsMap environments to specific domains
TCP RecordsGrey-cloud A/AAAA records for public databases
Drift Sync & HealthScheduled drift detection and health dashboard
Access PoliciesCloudflare Access app templating per domain

MCP Tools​

The MCP server includes 17 DNS tools for managing providers, domains, hostnames, and resource DNS status. Apps under wildcard domains need no DNS tool calls after initial provisioning.

See the DNS API reference for REST endpoints.
